# Fair-play and anti-cheat review

Reviewed: 2026-10-30, against the supplied CurveCoach rev145 source and the official pages below. This is a source-level risk review, **not** an anti-cheat compatibility test, legal opinion, publisher approval or guarantee against warnings, kicks, bans or rule violations. Detection behavior, game and event rules change; installed dependencies, drivers and exported curves applied with other software are outside this review. No Windows game, anti-cheat client or publisher was contacted or tested for this build. The supplied repository also retains an existing calibration-history file and backup directory; review these, exported patches and Git history for personal data before sharing the repository.

## Bottom line

For the lowest avoidable risk, close CurveCoach completely **before starting a protected game**; use its in-app Calibration and Training separately. Do not bypass anti-cheat, disable its protections, evade restrictions, or test questionable features on an account to see whether detection occurs. For actual permission, describe the exact feature and version to the game publisher and the competition operator, and obtain their written answer. A feature working, not being detected, or being off is not itself proof of permission. Closing the app reduces this app's runtime exposure; it is not a guarantee about other software or past behavior.

## What the code does and relative concerns

| Feature | Source-level behavior | Fair-play / anti-cheat concern |
|---|---|---|
| Calibration, Training and ordinary guidance | Operate in the app's own windows; adaptive targets are simulated locally. Raw mode uses foreground Windows raw mouse input in the app, temporarily grabs/confines the system cursor, and releases on focus loss/navigation. Curves are previewed/exported, not automatically installed or applied to a game. | Training separately and closing the app before play has less game-time exposure, but no risk-free certification. Other programs used to apply exported profiles are separate and may have their own rules. |
| Ordinary crosshair overlay | Separate topmost Qt desktop window; no game-process injection was found in this overlay. Off by default on a new install, but activation persists and may restore on later launches. | A visible crosshair can be considered an advantage or be unsupported by a game or tournament. Exact treatment is game-specific. |
| Dynamic Magnification | Off at each launch; captures and enlarges visible pixels around the crosshair on the primary display, not game memory. An optional, separately armed toggle polls a chosen key/button in the background. The overlay requests Windows capture exclusion to avoid seeing itself. | **Elevated policy risk** in live matches: enlarging the scene may provide visual assistance. Capture exclusion can make the overlay absent from some recordings and may concern operators. Do not assume it is permitted or that using Windows APIs makes it safe. |
| Capture preview / recording | User-started operating-system display or window capture; the preview can continue after leaving the Capture page. At app startup and on refresh, the window list enumerates visible window titles, process IDs and executable names, using `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` on Windows; it does not read process memory. Recording captures the primary display. | Game capture/recording rules and anti-cheat compatibility differ. Capture can contain live gameplay and private content; no approval is implied. |
| Live vision / Look now | Off at launch. User-directed sampled preview frames are sent to the configured model; Look now when not watching makes at most one request. Prompts request only picture/readability commentary, but a model can disregard them. | **Elevated policy risk** during a match: a model receives live gameplay frames and might generate actionable information despite the prompt. Treat it as real-time external assistance; do not use it during competitive play without explicit authorization. |
| In-Game Mode and voice | In-Game Mode converts manually entered values, off each launch. Continuous voice commands can listen in the background but execute app commands while the app/guide is focused. One-shot recognition may use an online service. | The arithmetic is not a game-memory integration, but rules can prohibit apps running or real-time assistance. Voice can be misrecognized; tournament rules may be stricter. |

A search of the supplied application and native source found no use of game-memory reading/writing, DLL injection into a game, game-input injection, aim/recoil automation, or automatic changes to game settings. This does not certify every dependency, compiled binary, installer script, or future modification. The OS process query above is real process access, even though it is not memory reading. Avoid characterizing the entire application as having no game/window access: capture can access visible game content, and the window enumerator can query a game's process name.

## Published policies: useful examples, not app approval

- **Fortnite / Epic:** Epic says third-party software is not officially supported and use is at the user's risk; support cannot determine or disclose whether a specific third-party program leads to a ban. Its separate crosshair support page says custom crosshairs are not supported. Those statements do **not** establish a specific ban for CurveCoach. [Epic: third-party software](https://www.epicgames.com/help/c-202300000001636/c-202300000001720/will-i-be-banned-if-i-use-third-party-software-with-fortnite-a202300000016487); [Epic: custom crosshairs](https://www.epicgames.com/help/c-34254770/c-33726977/can-i-personalize-my-crosshair-in-fortnite-a20560581).
- **VALORANT / Riot:** Riot's VALORANT developer policy says products serving its players must be registered regardless of API use; it also lists in-game apps/overlays with real-time data that immediately improves performance by altering behavior as unapproved, and separately lists static overlays that block parts of the map. Riot's player guidance prohibits unauthorized software giving an unfair in-game advantage. This policy does not specifically classify this build or every crosshair/magnifier; live vision or magnification are especially questionable and should not be used during a match without permission. [Riot developer policy](https://developer.riotgames.com/docs/valorant); [Riot cheating guidance](https://support-valorant.riotgames.com/hc/en-us/articles/10729504652691-Addressing-Cheating-in-VALORANT).
- **FACEIT:** Its current terms list unauthorized software including screen-analysis utilities, and its cheat guidance prohibits external assistance that gives an unfair advantage. That is a serious reason not to run live vision/magnification during FACEIT play absent explicit permission; the terms do not name CurveCoach or automatically classify every screenshot. [FACEIT terms](https://corporate.faceit.com/terms-conditions); [FACEIT cheat guidance](https://support.faceit.com/hc/en-us/articles/360015788779-What-is-deemed-to-be-a-cheat).
- **BattlEye:** Its FAQ says non-cheat overlays are generally supported unless game developers choose otherwise, and that specific programs may be kicked. This is general vendor guidance, **not** approval of CurveCoach, its magnifier or its use in a particular game. Game/tournament policies still apply. [BattlEye FAQ](https://www.battleye.com/support/faq/).
- **Apex Legends / EA:** EA prohibits cheating, including third-party tools used to gain an unfair advantage. This does not specifically decide whether any CurveCoach feature is permitted. [EA rules](https://help.ea.com/en/articles/apex-legends/play-by-the-rules/).

An anti-cheat warning or game launch block should be treated as a compatibility warning: close the app and consult the game's official support. Do not attempt to evade it. Check the game's terms, competition rules and official support for the exact game and intended feature before use.
