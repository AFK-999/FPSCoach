# CurveCoach (FPS Coach) Privacy Policy

Last updated: 2026-10-30 (rev145)

This policy describes the behavior of the supplied CurveCoach/FPS Coach code. Key points and controls are also on the app's Privacy page. Third-party services, modified builds and other software have their own practices. This technical policy is not a legal-compliance determination; a distributor should add its identity, contact and any legally required disclosures before release.

## Data kept on your machine

- **Training history** is saved to `.fpscoach_analytics.json` in the project folder. The Privacy page clears its contents by writing an empty list (the file can remain). The app retains at most 500 training results, including basic timestamps, scenario, hit/miss counts, accuracy and timing; partial/stopped drills may have basic results. AI Coach has a separate, session-only, off-at-launch opt-in to save aggregate in-app aim summaries for completed Training drills in the same history. It stores counts, click timing, endpoint error, target radius/speed and event-sampled tracking statistics, not raw pointer paths or individual tracking samples. Enabling mid-drill is marked partial. Incomplete drills do not save the new aggregate. Clearing training history deletes these summaries and turns collection off.
- **Preferences** are stored in your system settings store. This includes AI provider/URL/model, requested calibration sampling rate, model-list names, capture and recording choices (including the **Keep** checkbox and folder), voice and UI choices, and values typed in In-Game Mode. These are not cleared by the history buttons. Do not put secrets into a URL or another ordinary settings field.
- **Chat transcript** is kept by the app in memory for the current session. Clearing the chat on the Privacy page clears the app's transcript and history, not copies or logs retained by providers, OS facilities, backups or user exports.
- **Calibration guide answers** (aiming issues, grip, flick motion, pad size and optionally usable width, mouse model, game, DPI and in-game sensitivity) are optional self-reports. They remain in memory for this app session only, are not written to preferences or calibration history, and are committed on Finish or Preview in AI Coach. Cancel discards in-progress guide answers locally, but cannot recall a request already sent to the local service. The separate Crosshair tab applies changes immediately and saves preferences; position-edit mode, magnification and its key arm are session-only. The Application Guide describes these controls without changing them. Reopen the guide and choose **Clear saved answers**, or clear calibration history in Privacy. Existing chat messages and user-edited drafts must be cleared separately.
- A legacy `.fpscoach_calibration_history.json` may already contain older results. The Privacy control overwrites an existing file with `[]` rather than deleting it. New calibration results and recommendations are not written to that file. Timestamped cursor samples are processed in memory and discarded at the end of each accepted target. The analyzer retains movement metrics and cursor-speed samples from at most the latest eight accepted targets; older trials are evicted from that window. The app does not append new results to the file.

History clearing reports write failures but is not secure erasure. Old data may remain in backups, Git history, exports, cloud sync, logs, filesystem recovery or external services; manage those copies separately. The supplied source repository deliberately retains an existing `.fpscoach_calibration_history.json` and `.fpscoach-update-backups`; patches or Git history can also contain earlier content. Review and sanitize these separately before distributing a copy if they contain personal data. A kept recording, downloaded model or preferences are not deleted by history controls. The app provides no general encryption or third-party deletion guarantee.

## Calibration data

- Calibration runs only after you start the explicit 12-target in-app task. On Windows, raw mode registers foreground relative mouse input, identifies one source by an ephemeral Windows device handle and drives an in-app virtual cursor. It rejects unknown or mixed device handles; the handle is not saved or sent. Raw mode temporarily confines the shared OS cursor and grabs mouse input. Esc, focus loss, navigation, window move/resize, close or ownership failure releases capture. After returning, resume explicitly to restart the unfinished target. Failures prevent raw capture rather than silently using desktop input. Legacy mode samples desktop cursor positions while the app is active and the cursor is inside the task area. Neither path reads a game's input stream or uses screen frames for calibration. The app does not query hardware DPI; changes or physical drift are not measured or compensated.
- A hit with one observed movement segment can be counted, without inventing intermediate samples. Such sparse input cannot resolve unseen corrections; the confidence heuristic is reduced and the UI warns about it. An unusable trial is not counted; a new target restarts it. Movement metrics and the provisional sensitivity curve are calculated locally from the captured cursor movement. After each accepted target, the graph refreshes from the moving averages and speed samples of the latest eight accepted targets (or all available targets if fewer than eight). The generator selects a visually economical set of model anchors from domain-wide and measured-speed candidate positions. The anchors are not raw sample locations.
- Guide answers, including the motion choice, provide general educational guidance and optional AI context. The final review shows their exact normalized labels, with an illustrative top-down hand, wrist and forearm diagram; it is not a measurement of the user's body position or a diagnosis and does not modify the movement analyzer or measured scores. A model-generated factor can be previewed on an existing curve and changes the calibration chart only after explicit confirmation.
- Raw movement samples stay on this machine and are not sent to an AI provider. The calibration summary, up to 32 normalized recommendation model points, and up to 32 horizontal speed/gain points from the active calibrated or imported curve may be included in a text-coaching request, as described under **AI requests and network**.
- Calibration creates a recommendation for you to review. Export is explicit; the app does not apply a curve to a game or change game settings.

## Screen capture and recording

- Capture preview starts when you press Start on the Capture page and can keep capturing after you leave that page, until Stop or application close. It processes selected display/region/window frames in memory and can supply Live vision. A window-capture fallback can show the screen area behind the window, and if window bounds cannot be read it can fall back to the full output. Frames may contain game content, other apps or personal information. Calibration does not use these frames.
- **Recording (Capture tab, Recording card) is off unless you start it.** While it runs it records the primary display, either to a temporary file or, if you tick **Keep the recording**, to the folder you choose (`Videos/FPSCoach` by default).
  - Without **Keep**, cleanup attempts to delete a `bg_capture_*.mp4` scratch file from the system temporary directory on Stop or normal close. A crash, forced termination, locked file or deletion error can leave it behind; check and remove it manually. Deletion is not secure erasure.
  - With **Keep**, the file stays in that folder until you delete it, including across app restarts, and is normally named `fpscoach-recording-<date>-<time>.mp4`; if renaming fails, the original scratch name can remain.
  - Recordings are never uploaded by the app. Anything you do with the file afterwards (send it, sync it, or open it elsewhere) is up to you.
- The recording analysis timer samples frame statistics (size and mean brightness) as a pipeline health check. It does not look for targets, shooting, or gameplay events.
- The capture window list is populated when the app creates the Capture page at startup and when refreshed. It enumerates visible window titles, process IDs and executable names so you can choose a window; it reads a selected window's rectangle when capture starts. On Windows it opens a process with limited query rights to obtain its executable name, then closes the handle; it does not read or write that process's memory. Capture itself uses operating-system display/window capture APIs and can show game content.

## AI requests and network

- **Dynamic performance curve** is off at every launch. When enabled in Recommendation or Training, it collects only within the in-app Calibration and Training tasks: visible-target click accuracy, individual target-to-click app-event times, endpoint error, observed pointer or virtual-cursor speed, path length, movement-event count and path efficiency, target radius, adaptive target speed at the click when applicable, source and training scenario/moving-target flag. Up to 32 recent attempts per source and the user-set goals stay in session memory. It does not collect raw cursor coordinates for the request, read a game, or use screen frames. For an unchanged generated calibration baseline with a matching input path, the calibration-derived speed reference and approximate mean-speed fractions are included; no physical sensor speed is inferred. Goals, these attempt records and sampled baseline speed/gain points are sent only to a configured loopback Ollama service after model metadata checks; as with guide analysis, a local service can forward data unless Ollama cloud is disabled and restarted. The model is not downloaded automatically. Requests may finish after disabling; results are ignored. Turn the feature off to discard its records; clearing training history or calibration history also turns it off and clears them. Training's separate saved analytics are controlled by the existing clear button. Generated factors are validated, proposals are preview-only until explicit confirmation, and no game/device/OS settings are changed.
- **Adaptive Calibration** is off by default and uses a deterministic local controller, not a model request. It uses a rolling window of up to eight in-app visible-target click outcomes to adjust size and movement speed; it does not collect game input or new background data. Moving-target scores use the click-time target center, not the complete target trajectory.
- **Daily warm-up** is requested explicitly in AI Coach. The app sends grouped scenario names and hit/miss counts from up to 30 saved Training sessions to checked loopback Ollama, after verifying local-model metadata; it sends no timestamps, raw paths, screen frames or game input for this request. The model's routine is validated, never starts drills automatically, and may be uncertain. A request already sent cannot be recalled. Loopback Ollama may forward requests unless its cloud features are disabled and restarted. Clearing Training history prevents future use and invalidates a pending result.
- **Session-based playstyle analysis** runs only on explicit request in AI Coach. It sends up to 30 sanitized saved training-session summaries, the chosen playstyle, accuracy and click-time goals, and sampled current-curve gains to a checked loopback Ollama endpoint, after local-model metadata checks. No raw coordinates, pointer paths, screen frames or game input are sent. Event-sampled tracking precision is not a time-weighted or game-performance measurement. An already-sent request can finish after history is cleared, but its result is discarded; a local Ollama service can forward data unless cloud is disabled and restarted. The validated ±10% preview requires explicit confirmation and never changes game or device settings. Existing saved basic session statistics may be used even if detailed collection is off.
- Regular text-coaching and Live vision requests use the configured endpoint, which may be remote even when the provider is labeled Ollama. Requests also include the app's system instructions and any extra persona/instructions loaded from `config/ai_profile.toml`; do not put secrets in that file. AI Coach Focus choices persist and can trigger automatic coaching requests after calibration or training while enabled. Providers may retain requests under their own policies. A loopback Ollama service may itself forward data unless its cloud features are disabled. Regular requests use standard URL handling, including system proxy and redirect behavior; the guide and other explicitly verified local-only features have stricter loopback checks. Normal chat can automatically ask Ollama to download a missing model. Manual model listing, connection checks, model downloads, voice setup and build/bootstrap scripts can also access network services. The current Settings UI has no API-key field; do not assume an authenticated hosted-provider workflow is available.
- Guide local AI is on by default each time the optional guide opens and can be switched off. Changes to selections or setup automatically queue a request after a short debounce; the request includes in-progress self-reports, optional setup (including model, game, DPI and sensitivity), and an available numeric session summary, but no raw movement coordinates. The app connects only to the configured loopback Ollama endpoint, bypasses proxies and redirects, checks installed models and refuses known cloud tags or remote metadata, and does not download a model. **Loopback alone cannot prove the service will not forward data:** disable Ollama cloud features with `OLLAMA_NO_CLOUD=1` or `disable_ollama_cloud` in Ollama's server configuration and restart it for local-only use. An existing request may finish after disabling AI or closing the guide. Responses are untrusted and factors bounded to ±10%; graph changes require explicit confirmation and never change game settings. Preview in AI Coach reuses the completed local result without making another provider request, displays it in the local transcript and sends it to the existing text-to-speech engine only if spoken replies are enabled. The result is not added to provider-bound chat history by this preview action.
- Finished guide answers and selected aiming motion can also be included as self-reported context in regular text-coaching requests (including enabled proactive coaching and online providers). Opening the separate discussion draft does not send it. They are not included in Live vision text context, although captured preview frames could show the guide or selection UI. Clearing them cannot recall data already sent to a service; earlier chat content can still contain it. Guide setup values are independent of In-Game Mode and can be sent as guide context even when that mode is off.
- Text-coaching requests can include the conversation, numeric calibration summary, up to 32 normalized recommendation model points, and up to 32 horizontal speed/gain points from the active curve. Raw cursor samples are not included. If In-Game Mode is on, the numbers you typed for that mode are also included; with it off, that mode’s own values are not sent. Separately, finished guide answers may include game, DPI and sensitivity regardless of that toggle.
- **Voice commands** are optional and the enabled preference is saved. While enabled, the continuous Vosk listener opens the microphone and recognizes speech locally, including while the app is not focused; it executes recognized app actions only while the app or its guide is focused. Setup may automatically install voice packages and download a Vosk model. Commands do not require a wake word and may be misheard, including speech from other people; disable the listener when unwanted. Except for “stop speaking,” commands are ignored while the app reports its own speech playing, and while the separate one-shot mic is active; this cannot guarantee echo prevention. Recognized “ask …” questions, an unmatched configured wake-word phrase, and “explain my calibration” are sent as text with normal coaching context to your configured AI provider, which can be online. Unsent chat drafts are not replaced and busy requests are not interrupted by this command path.
- **AI Coach one-shot microphone** is separate from continuous commands. If the optional SpeechRecognition backend is installed, it uses Google online recognition and sends captured audio to that service; otherwise it can use local Vosk. The recognized question is then sent to the configured coach provider. Avoid using the one-shot mic and continuous listener simultaneously.

## Live vision (AI Coach)

- **Hidden and off until you ask for it.** The panel is not shown unless **Settings → Enable live vision** is on; that layout preference is remembered. Enabling it only shows the panel: **Watch live** still starts off at every launch and is not saved.
- While watching is on, CurveCoach samples the capture preview into short clips of downscaled frames (4 frames half a second apart by default) and sends one clip at a time to the configured AI endpoint, waiting for each reply before sampling the next. Frames are reduced to at most 768 px wide JPEGs. This feature records nothing to disk.
- Frames go to the configured endpoint; a remote server receives them. A loopback Ollama server may still forward data: disable its cloud features and restart it for local-only operation, and check the service's own configuration. Providers can retain received data. The in-app filmstrip can retain the last clip in memory for display after the request; the capture backend may retain its latest preview frame. This feature does not intentionally save clips to disk.
- The model is asked to comment on the setup and picture (screen or mode, layout, HUD clutter, lighting, colour, blur, and readability). Prompts instruct it not to identify targets, enemies, or players and not to give aim, recoil, or movement guidance, but a model may ignore instructions or produce such content. **Look now** explicitly requests at most one clip even when Watch live is off; it does not start the continuous loop. If already watching, it requests a look within the active loop.
- Turning Watch live off stops new automatic requests; a request already in flight can finish. **Look now** can separately send a clip while watching is off. Stop Capture separately to stop the underlying preview.

## In-Game Mode

- **Off at every launch.** It turns on only when you enable it in Settings for the current session; the on/off state is not saved.
- When on, the values you type (game, mouse DPI, in-game sensitivity, and optional measured 360° distance) are stored in your settings store so the card is pre-filled next time. CurveCoach does not read them from your mouse, game, or configuration files.
- CurveCoach never reads, hooks, or changes the game for this feature: there is no game-window access, memory access, input injection, or game capture. The conversion is arithmetic on your numbers.
- While the mode is on, those numbers and the resulting conversion/suggestion are included in context sent to your configured AI endpoint. With the mode off, that mode’s own values are not sent. Independently entered guide setup answers may still be sent as guide context.
- If your game or competition requires other applications to be closed, exit CurveCoach entirely; merely switching off In-Game Mode does not close its other features.

## Crosshair overlay

- The crosshair overlay is **off by default for a new installation**, but its activation state is saved and can restore the overlay on a later launch. When it is on, or while you edit its position, it draws a crosshair on your primary screen only. Close the app before protected play if unsure.
- The active crosshair overlay does not interact with or inject into any game process. It does not hook input or read or write game memory. The ordinary crosshair alone does not capture screen pixels.
- **Dynamic Magnification** is separate and off each launch. Only while enabled, it repeatedly captures a small region of visible primary-screen pixels, which can include game content, and enlarges them locally. Only the current image is retained in memory; this feature does not save or send those pixels. Disabling, hiding the overlay or entering position edit mode stops it.
- The optional binding requires a separate session-only arm checkbox. While armed and the crosshair is active and locked, the app polls only the selected keyboard key or physical mouse button in the background; it does not hook or consume input. Polling can miss fast presses and conflict with game bindings. It stops when disarmed, editing, hiding or exiting. The binding choice persists, but neither arming nor magnification persists.
- Windows 10 version 2004+ is required. The overlay requests and verifies Windows capture exclusion before capturing, and stops if that request or a grab fails or its native window changes. Error 8 on a layered overlay triggers a compatibility retry with the original window style restored before verification; failure is shown and capture remains off. Exclusion is capture-path dependent and can cause the overlay to disappear in screen recordings; it is not guaranteed to prevent feedback in every path. Turn it off if recursive feedback appears. Protected content, secure desktops and exclusive-fullscreen games can be black, stale or unavailable. Check game and anti-cheat rules before enabling; magnification may be considered a gameplay advantage.
- When locked, it ignores the mouse so clicks reach the game. Its position is saved on your machine.

## Fair-play boundary

CurveCoach is primarily a coaching and calibration tool. The code inspected has no built-in game-memory reading/writing, game-process injection, automated game-input injection, aim/recoil automation or automatic game-setting changes. Window enumeration uses limited process-query access as described above. The optional desktop magnifier displays enlarged visible screen pixels and may confer an in-game advantage; a crosshair overlay, real-time vision, recordings or other external tools can also be restricted by game or tournament rules. Live vision prompts request picture/readability commentary rather than target or aim analysis, but model output is not technically guaranteed to obey that instruction. Do not use these features in matches unless the relevant operator permits them. No anti-cheat compatibility or ban-free use is guaranteed; see [Fair-play and anti-cheat review](FAIR_PLAY_REVIEW.md).
