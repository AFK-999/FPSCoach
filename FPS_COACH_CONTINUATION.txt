--------------------------------------------------------------------------------
FPS Coach — a high-performance Windows desktop application for first-person
shooter players.

  - C++ core:  real-time screen capture + movement analysis (perf-critical path)
  - Python UI: user-facing interface, workflows, settings, AI chat
  - Coupling:  Python "editable install" (pip -e) linked to the project tree
  - Tooling:   Windows batch (.bat) scripts for setup / launch / self-repair

3. CURRENT TASK (what we are building now)
--------------------------------------------------------------------------------
Produce TWO distinct build packages, plus backend hardening and AI preconfig.

  TASK A — Two build packages:
    A1. "Lite" / foundation build:
        - Ships WITHOUT any AI models or Ollama runtime.
        - User installs Ollama themselves and downloads models themselves.
        - App detects Ollama + models at runtime and guides the user if missing.
    A2. "Full" build:
        - Embeds the Ollama runtime AND Qwen 3 1.7B model weights in the installer.
        - AI is fully functional out of the box, no manual setup.

  TASK B — Environment self-repair (backend):
        - On startup, backend checks the local environment.
        - If the project folder was MOVED or RENAMED, auto-repair the install
          (re-point the editable install / fix path references) before running.

  TASK C — AI chat preconfiguration:
        - A dedicated configuration section to purposefully import
          instructions + recommendations into the AI chat interface.
        - Goal: the assistant is pre-configured (system prompt / persona /
          domain guidance) to effectively fulfill its FPS-coaching role.

4. IMPLEMENTATION PLAN / SPEC (ready for whoever has the real files)
--------------------------------------------------------------------------------

4.A  BUILD PACKAGES
  - Introduce a build flavor switch, e.g. an env var / CLI flag:
        FPSCOACH_BUILD_FLAVOR = "lite" | "full"
  - Shared build steps compile C++ core + package Python app; flavor only
    changes which AI assets are bundled.
  - LITE:
        * Do NOT bundle Ollama or weights.
        * Installer stays small.
        * First-run wizard: detect Ollama (`ollama --version` / API ping on
          http://localhost:11434), detect required model; if missing, show
          instructions + a "Download model" helper (calls `ollama pull`).
  - FULL:
        * Bundle the Ollama runtime binary for Windows.
        * Bundle Qwen 3 1.7B weights (model tag e.g. `qwen3:1.7b`).
        * Installer copies runtime + weights into app data; on first run,
          start/point to the bundled Ollama and preload the model.
        * Verify licensing/redistribution terms for Ollama + Qwen weights
          before shipping embedded (ACTION ITEM — confirm, see §9).
  - Suggested artifacts:
        dist/FPSCoach-Setup-lite-x64.exe
        dist/FPSCoach-Setup-full-x64.exe
  - Likely installer tooling: Inno Setup or NSIS (confirm what project uses).
  - A single build script should take the flavor as a parameter, e.g.:
        build.bat lite   |   build.bat full

4.B  ENVIRONMENT SELF-REPAIR (backend)
  - Add a startup check (Python, runs before UI loads) that:
        1. Reads the recorded install path (saved at last successful run).
        2. Compares to the current actual project path.
        3. If different (moved/renamed) OR editable install points to a
           non-existent path -> trigger repair:
              - Re-run `pip install -e .` against the current path, OR
              - Rewrite the *.egg-link / *.pth / finder entries to the new path.
        4. Persist the new path for next time.
  - Reuse/centralize logic already in the repair .bat scripts so batch and
    Python share one canonical repair routine (avoid drift).
  - Must handle spaces AND non-ASCII in paths (quote everything).

4.C  AI CHAT PRECONFIG
  - New config section (e.g. config/ai_profile.* or a settings page) that holds:
        * system_prompt / persona (FPS coaching role, tone, constraints)
        * curated instructions + recommendations ("knowledge" / guidance)
        * default model, temperature, max tokens, backend (ollama/openai)
  - Loaded and injected into every chat session automatically.
  - Make it importable: allow loading an instructions file so the profile can
    be versioned and shared. Validate on import.
